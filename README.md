# C++ 面试练习台

访问：<https://qzshen219-pixel.github.io/cpp-interview-lab/>

面向 C++ / 后端校招的浏览器学习工具。保留现有题库、每日练习和云盘项目题，支持电脑与手机。使用 GitHub Pages 从 `main` 分支根目录发布，无需构建或服务端账号。

## 学习功能

- **全文搜索**：按“全部内容 / 题目与代码 / 参考答案与易错点 / 我的作答与笔记”搜索，支持空格分隔的多个关键词、大小写和全角字符等价匹配。结果显示命中片段与高亮；选择参考答案范围时自动展开解析。个人内容始终只在本机检索。输入停止 160 毫秒后更新结果，清除筛选恢复默认范围。
- **答案历史与恢复**：每次保存新作答保留版本，逐题查看与当前内容的按行差异；恢复前保留原已保存作答和非空草稿。每题最近 10 版、全站最多 100 个存储版本，当前已保存作答始终可查看。旧版只有当前作答的记录仍可恢复；升级前已经被覆盖且没有备份的内容无法追溯。历史随学习备份导出和合并，重置同步清除历史。
- **学习周报**：按北京时间周一至周日查看本周及前七周，提供每日练习柱状图、练习天数、覆盖题数、较前一周练习量、客观题正确率、文字表达自评分布、模块成绩和到期复习任务完成率，可导出 Markdown。正确率只统计已答客观题，未答题单列；自评取每题本周最后一次评价。到期任务包括本周到期及此前未完成任务，提前调整的任务排除；未答题不算完成到期复习。旧每日练习量保留，缺少日期明细的旧成绩不回填。成绩与复习明细保留 90 天，最多 2000 条成绩、1000 条已结束任务；未完成任务继续保留。

- **长期保存与备份**：答案、草稿、掌握程度、收藏、笔记、自测和项目面试记录自动保存在本机浏览器；首次升级时迁移当前标签页中仍存在的旧记录。通过“学习备份”导出 JSON 文件，可在另一台设备合并导入。作答按逐题记录合并，笔记、收藏、复习安排和测验结果按各自的修改时间分别合并；同项保留较新修改，取消收藏或主动清空笔记也会保留。旧备份继续可用，旧备份中的默认空笔记不会覆盖已有笔记。空设备同时恢复练习设置与上次位置。
- **间隔复习**：保存文字回答后进行自评。“需要复习”安排在 10 分钟后；“基本掌握”从 1 天开始，后续约翻倍；“熟练表达”从 3 天开始，后续约乘 2.5。当天同一作答重复点击同一评价不会重复延长间隔。选择题按实际结果更新复习安排；文字题采用自评。
- **每日计划**：每日目标可选 5 / 10 / 15 / 20 题，可限定 IM、云盘或通用方向。优先安排到期复习，结合已有评价选择薄弱模块，并混入新题。当天的同一道题只计入一次练习量。每日计划按北京时间切换，调整目标时保留已完成的匹配题目。
- **复习日历与模块分析**：查看未来七天的复习安排、当前到期题和需要强化的题目。模块掌握度根据选择题结果及主观自评计算，尚未评价的文字回答不参与掌握度计算。
- **自定义自测**：可选 5 / 10 / 20 题、题型比例、错题优先及 0 / 5 / 10 / 20 / 30 / 60 分钟时限。范围沿用项目、来源、模块和状态筛选。题量或某一题型不足时按现有题目补足；选择单一题型时遵从题型筛选。到时自动交卷，未答题标记为未作答，不计入已完成题数。关闭页面不会暂停计时。
- **项目模拟面试**：选择 IM 或云盘，进行 5 / 10 轮主问题与追问，支持不限时或 10 / 20 / 30 分钟。作答时隐藏参考答案，结束后逐轮对照题库要点自评。保留最近 10 次面试记录；同题主问题和追问按已评价轮次中的最低掌握度安排复习。
- **收藏与个人笔记**：逐题收藏、记录自己的项目例子与口述答案，并通过收藏夹、笔记筛选快速找到。
- **手机离线使用**：首次联网完成题库缓存后，可断网打开网站练习。页面显示缓存状态，可手动更新离线题库。支持安装的浏览器提供安装入口，其他浏览器显示添加到主屏幕的指引。

个人学习记录保存在当前设备的浏览器中，跨设备通过备份文件手动迁移。清理网站数据或使用临时浏览模式可能使本机记录丢失，建议定期导出。输入停止 300 毫秒后批量保存；切换题目、导出备份、页面隐藏或离开时立即保存。打字期间不重建日历和掌握度列表。存储不可用时页面明确提示导出备份，尽可能用当前标签页的临时存储保留内容；文件导入先预览，再确认合并。

重置会产生本浏览器的重置版本，并同步到其他已打开的新版页面。页面每次写入前也会检查共享存储，防止暂停的旧页面覆盖重置结果。显式导入旧备份仍可恢复内容，备份中的其他设备重置版本不会覆盖本设备版本。更新后请刷新旧页面，使其使用新的保存逻辑。

## 文件结构

| 文件 | 职责 |
| --- | --- |
| `index.html` | 页面入口、学习概览、筛选与备份对话框 |
| `app.js` | 逐题练习、自定义自测、项目面试、状态及页面交互 |
| `learning-core.js` | 记录校验与迁移、复习、选题、版本历史、周报统计与备份合并 |
| `learning-search.js` | 搜索索引、Unicode 匹配、命中片段与安全高亮 |
| `learning-insights.js` | 答案对比与恢复、周报弹窗和导出 |
| `learning-ui.js` | 每日计划、复习日历、掌握度、备份导入导出、离线与安装状态 |
| `styles.css` / `ui.css` / `learning.css` | 原有视觉、动态背景与新增学习界面 |
| `questions.js` / `daily-questions.js` / `extra-questions-*.js` / `cloud-disk-questions.js` | 按顺序加载的现有题库 |
| `sw.js` / `manifest.webmanifest` / `icon-*.png` | 站点范围内的离线缓存及安装资源 |

## 开发与验证

Node.js 20 或更新版本：

```sh
npm ci
npm test
npm run check
```

自动检查覆盖记录迁移、跨页面恢复、存储失败、备份冲突、复习安排、每日换日、题型配比、限时自测、项目面试、输入转义、离线导航、弱网超时、整套缓存切换、更新失败回退、跨页面重置、输入批量保存、全文检索与转义、历史合并恢复、周界日期、到期任务和周报导出等流程。DOM 测试使用 JSDOM，Service Worker 测试使用 Cache / Fetch API 的受控模拟，真机安装和实际断网体验需在浏览器中验证。

## 发布与更新

GitHub 仓库 **Settings → Pages → Deploy from a branch → main → /(root)**。

`.nojekyll` 保持存在，提交即触发 GitHub Pages 部署。所有资源使用相对路径，适用于 `/cpp-interview-lab/` 子路径。

修改应用逻辑或样式时，同时提升 `index.html` 中对应资源的版本参数与 `sw.js` 的 `VERSION`。新 Worker 就绪后页面提供“更新到新版本”按钮；自测或面试尚未结束时先完成当前练习再更新。

离线安装会缓存页面当前引用的全部本地题库与应用资源。缓存中的页面和资源直接读取，不等待弱网请求；未缓存请求最多等待 4 秒。更新先下载到独立快照，每个资源（含响应正文）最多等待 12 秒；全部下载并校验存在后才切换快照。失败或超时保留完整旧版本，清理未完成的下载。新 Worker 等待用户应用更新期间保留旧 Worker 的缓存。

题库扩充后，可联网打开网站并点击“更新离线题库”，下次打开使用完整的新缓存。为保证版本完整，已有缓存页面不会被后台获取的一份新 HTML 单独替换。缓存只覆盖本仓库路径，并且仅清理本应用的旧版本缓存；同一发布版本最多保留当前及上一份完整快照。
